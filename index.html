挑戰前提

導入前先想清楚的六件事

1. 它預設你有程式碼 repo 和 issue 系統

Engineering 類幾乎都要讀寫 issue tracker。非開發同仁能直接受益的主要是 Productivity 類（grill-me、to-questionnaire、handoff、teach）。

2. 每個 repo 要先跑一次 setup

沒跑 /setup-matt-pocock-skills，to-spec、to-tickets、triage 都會請你先回去設定。用 GitLab 的團隊要確認機器上有 glab CLI。

3.「AI 自動觸發」不是保證

AI 是否會自己叫用，取決於你的描述是否命中該 skill 的說明文字。重要步驟（如 tdd、code-review）不確定時，直接打 /名稱 最可靠。

4. 預設語言是英文

GLOSSARY.md、ADR、wait-what 都以英文設計，wait-what 甚至指定「簡化技術英文」。中、越、英混用的團隊，要先決定詞彙表用哪種語言，否則會出現三套術語。

5. 平行執行很耗用量

/implement-spec 會同時開多個子 agent 各自寫程式。速度快，但 token 成本是單線的好幾倍，適合工單多且相依關係清楚的規格。

6. 本頁沒收錄的部分

repo 另有 misc/（4 個）與 in-progress/（7 個）資料夾，README 未列為正式技能，可能隨時變動，所以不收錄。

術語小抄（看不懂的詞先查這裡）
Issue tracker
記錄待辦與問題的系統，例如 GitHub Issues、GitLab Issues。
Spec 規格
一份說清楚「要解決什麼問題、怎麼算完成」的文件。
Ticket 工單
從規格切下來、一次做得完的一小塊工作。
Tracer bullet
曳光彈切法：每張工單都從資料庫一路貫穿到畫面，做完就能展示，而不是先把整層資料庫做完。
TDD
測試驅動開發：先寫一個會失敗（紅燈）的測試，再寫剛好讓它通過（綠燈）的程式。
Seam 接縫
可以從外面觀察、測試程式行為的介面位置，不用拆開內部。
Deep module
深模組：用很簡單的介面就能使用很多功能，像電視遙控器只有幾顆鍵卻能控制複雜的機器。
GLOSSARY.md
專案詞彙表，讓人和 AI 對同一個詞有同一個意思。
ADR
架構決策紀錄：寫下「當初為什麼這樣決定」，避免日後重吵。
Sub-agent
主 AI 派出去做特定任務的分身，有自己獨立的記憶空間。
